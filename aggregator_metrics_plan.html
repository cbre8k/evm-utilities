1. The Core Challenge: Standardization (Adapter Pattern)

As highlighted in reviews, the biggest technical difficulty is standardizing the outputs of each DEX aggregator API so that quotes align. Providers represent tokens, amounts, decimals, and gas estimates in vastly different structures.

To solve this, we will introduce a strict Adapter Architecture. The server-side request flow will wrap each aggregator-specific response in a unified parser module.

Aggregator Inconsistencies & Unification Strategy:

  • Native Gas Token Representing:
    • 0x: Uses 0xeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeee.
    • 1inch: Uses 0xeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeee.
    • OKX: Uses 0x0000000000000000000000000000000000000000 or "ETH" depending on API version.
    • KyberSwap: Uses 0xeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeee.
    • Solution: Normalize native token addresses to a standard identifier internally before executing queries.
  • Decimals & BigNumber Safety: Some APIs return strings, some return numbers, and some return Hex values. We will shift raw amounts to formatted decimals using token registry data: 
    outputAmountFormatted = new BigNumber(outputAmountRaw).dividedBy(new BigNumber(10).pow(tokenOutDecimals)).toFixed(6);
  • Gas Estimates Mapping: Different aggregators specify gas differently (e.g. gas limit vs total gas cost). We will normalize this to estimatedGasLimit, and compute the estimated gas cost in Wei using the current network gas price fetched in real-time.

Unified Quote Type Structure

export interface StandardizedQuote {
  provider: '0x' | '1inch' | 'okx' | 'kyber' | 'stormlink';
  success: boolean;
  outputAmountRaw: string;       // e.g. "1200500000" for 1200.5 USDC
  outputAmountFormatted: string;  // e.g. "1200.5000" (decimals-adjusted)
  estimatedGas: string;          // gas units limit (e.g. "115000")
  gasCostWei?: string;           // (estimatedGas * currentGasPrice)
  error?: string;                // Error details if API request fails
  latencyMs: number;             // Response time
}

2. Data Adapters Specifications

A. 0x Adapter

  • Endpoint: https://api.0x.org/swap/v1/quote
  • Mapping Logic: Parse response parameter buyAmount as the output amount, and estimatedGas as gas.

B. 1inch Adapter

  • Endpoint: https://api.1inch.dev/swap/v6.0/1/quote
  • Mapping Logic: Parse response parameter toAmount as output, and gas as gas. Requires header Authorization: Bearer [KEY].

C. OKX Adapter

  • Endpoint: https://www.okx.com/api/v5/dex/aggregator/quote
  • Mapping Logic: Parse response parameter data[0].toTokenAmount as output, and data[0].gas as gas.

D. KyberSwap Adapter

  • Endpoint: https://aggregator-api.kyberswap.com/v1/routes
  • Mapping Logic: Parse response data.routeSummary.outputAmount as output, and data.routeSummary.totalGas as gas.

E. Stormlink Adapter

  • Endpoint: Configurable via environment variables.
  • Mapping Logic: Standardized parser conforming to the custom API specs you provide. Falls back to a mock adapter generating variance rates if endpoint vars are missing.

Rolling counters to compute ratios quickly. Keys: aggregator:stats:{provider} (e.g. aggregator:stats:0x):

  • total_queries: Incrementing integer of requested quotes.
  • success_queries: Count of valid quotes returned successfully.

  • cumulative_deviation: Cumulative percentage points below the best quote (used to calculate average underquote deviation).

5. Mathematical Models & Metrics Formulation

The core objective is to analyze underquotes and overquotes. These terms are defined and computed mathematically as follows:

A. Best Quote Identification

For any query $q$, the set of successful quotes is $Q_q = \{A_{p,q} \mid p \in \text{Providers}\}$. The best quote output amount is defined as:

$$M_q = \max(Q_q)$$

B. Overquote / Best Quote Rate ($OR_p$)

Measures how frequently aggregator $p$ wins the best rate race over $N$ total queries:

$$OR_p = \frac{\sum_{q=1}^N \mathbb{I}(A_{p,q} = M_q)}{N} \times 100\%$$

(where $\mathbb{I}$ is the indicator function, returning 1 if true, 0 otherwise)

C. Underquote Deviation ($UD_{p,q}$)

For a query $q$, if provider $p$'s quote $A_{p,q}$ is not the best, the underquote percentage indicates the deviation loss:

$$UD_{p,q} = \frac{A_{p,q} - M_q}{M_q} \times 100\%$$

The average underquote deviation ($AUD_p$) across all queries where the provider failed to win is: $$AUD_p = \frac{\sum_{q \in \{q \mid A_{p,q} < M_q\}} UD_{p,q}}{\text{Count}(A_{p,q} < M_q)}$$
